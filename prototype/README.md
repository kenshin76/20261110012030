# 재활용 실적 이상탐지·모니터링 시스템 [프로토타입] — RE:CHECK

가상 조합·가상 데이터로 만든 시연용 내부 업무 시스템입니다. 정적 파일(HTML·CSS·JS)만으로 동작하며, 판정·규칙 변경·감시 목록·모델 버전·감사 로그는 브라우저 localStorage에 저장됩니다. 실제 통합 API·관리표·계량 시스템·국세청·지도 서비스와 연결되지 않습니다.

## 실행

- GitHub Pages 또는 아무 정적 서버에서 `index.html`을 엽니다. (예: `python3 -m http.server`)
- 로그인 → 2단계 인증(체험용 인증번호가 화면에 표시됨) 순서로 들어갑니다.
- 화면 왼쪽 아래 「체험 도구」에서 역할을 바꾸거나 체험 데이터를 초기화합니다.
- 로그인 화면 아래에서도 체험 데이터를 초기화할 수 있습니다. 로그인 인증번호의 유효시간은 5분입니다.

## 시연의 한계

- 모든 사업회원·사업장·차량·사업자번호·수치·사진은 가상 데이터입니다. 계량 사진은 사진처럼 생성한 차량 이미지 10종(색상·주야간 5종 × 적재·공차)을 사용하며, 번호판·카메라 ID·촬영 시각은 체험용 값으로 합성합니다. 실제 촬영 증빙·번호판 인식 모델·이미지 비교 연산이 아닙니다.
- 탐지 결과·사전 계산·백테스트·재학습 결과는 시연용으로 미리 만든 값과 계산식입니다. 실제 SQL 실행·모델 학습이 아닙니다.
- 2단계 인증·권한·감사 로그는 화면 동작 시연용이며 실제 서비스의 서버 인증·인가·위변조 방지 저장소를 대신하지 않습니다. 실제 개인정보·비밀번호를 입력하지 마세요.
- 공단 결과의 엑셀 등록은 샘플 절차 안내입니다. 실제 파일을 분석·적재하지 않습니다. 감시 목록의 소급 탐지 결과는 저장하지만 운영 대기열에 자동 추가하지 않습니다.
- 로그인·오늘의 점검·데이터 연동·보고서의 사진은 서비스 분위기를 위한 생성 이미지입니다. 차량 사진 역시 실제 분석 입력이나 모델 평가 자료로 사용하지 않습니다. [이미지 제작 기록](assets/images/README.md)을 참고하세요.

## 2026-11-10 검토 반영

- 네이비·미네랄 틸·밝은 회색으로 색상을 정리하고 시설·자원 검수 사진 2종을 적용했습니다. 설명 중심의 로그인 문구와 업무 안내를 간결하게 정리했습니다.
- 화면 이동·로그아웃·역할 변경 시 확인창과 미완료 예약 작업을 취소합니다. 모달을 닫으면 해당 재학습·소급 판정 작업도 중단됩니다.
- 담당자는 담당 권역의 건만 판정·담당자 변경할 수 있으며 전체 권역 조회는 유지합니다. 필터를 바꾸면 숨겨진 선택을 해제합니다. 분석가의 감시 등록, 담당자의 SQL 실행, 관리자 승인 작업의 권한을 확인합니다.
- 판정 중량은 숫자·범위·결과/사유 일치 여부를 확인합니다. 새 규칙의 기준값도 검증하고, 0인 기준값의 슬라이더 범위를 정상화했습니다. 규칙 등록을 취소하면 케이스 카드 상태를 바꾸지 않습니다.
- 기준값·알림 사용 설정을 저장합니다. 회원사 상세의 대기열 링크에 회원사 필터를 전달합니다. 대량 내려받기 승인은 요청 계정별로 구분하고 실제 출력 행 수를 표시와 맞췄습니다.

### 추가 상태 연계 점검

- 규칙의 사전 계산은 원래 기준값을 계산 기준으로 유지해 승인 후에도 같은 입력에 같은 건수를 표시합니다.
- 알림창은 규칙 이름 등 입력값을 HTML 태그로 해석하지 않고 문자로 표시합니다.
- 사진 재처리는 점검 담당자·관리자만 실행하며 샘플 인식 결과와 처리 이력을 저장합니다. 페이지 이동·계정 변경 시 미완료 처리는 취소되고, 완료 결과는 새로고침 후에도 유지됩니다. 실제 AI 추론은 수행하지 않습니다.
- 차량 도식은 사진형 생성 이미지 10종으로 교체했습니다. 같은·유사 사진의 비교 관계, 적재·공차 상태, 번호판 인식 영역, 얼굴 가림·30초 원본 열람을 유지합니다. [차량 사진과 제작 프롬프트](assets/images/vehicles/README.md)를 참고하세요.

## 검수 실행

Node.js와 Playwright가 설치된 환경에서 실행합니다. Chrome을 사용하려면 `PW_CHANNEL=chrome`을 지정할 수 있습니다. 화면·이미지와 테스트 결과는 `SHOTS` 또는 운영체제 임시 폴더의 `recheck-shots`에 저장됩니다.

```sh
node tests/smoke.cjs
node tests/flow.cjs
```

추가 회귀 검사는 이 폴더를 로컬 서버로 연 뒤 실행합니다(기본 `http://127.0.0.1:8910`, 다른 주소는 `BASE_URL`로 지정).

```sh
node tests/regression.cjs
node tests/interaction.cjs
node tests/photos.cjs
```

2026-11-10 로컬 Chrome 검수에서 데스크톱 1440px·모바일 390px의 19개 경로 순회에 오류가 없었고, 주요 흐름 20개 및 추가 회귀 검사 133개 확인 항목이 통과했습니다.

차량 사진 교체 후 같은 검사를 다시 통과했으며, 사진 전용 검사 10개도 통과했습니다. 4개 탭의 이미지 로딩·번호판 일치·사진 재사용 비교·얼굴 30초 재가림·상세 화면 적재/공차 구분·차량 이미지 10개 로딩과 모바일 가로 넘침을 확인했습니다.

### 최종 전체 검토

- 일일 작업의 운영 규칙 수는 초기 운영 상태(44개)에서 계산하도록 맞췄습니다. 이미 완료된 배치의 값이므로 이후 체험 중 규칙을 변경해도 해당 배치의 표시는 유지합니다.
- 신규 케이스 N02의 제목을 설명에 맞게 「동일 차량 외형의 번호판 변경」으로 정리하고, 지연 알림의 「늦게 도착한 분」을 「늦게 도착한 자료」로 고쳤습니다.
- 감시 목록 등록 완료 후 Esc로 창을 닫아도 새 항목이 즉시 표시되도록 수정했습니다. 등록 도중 닫는 경우에는 기존처럼 미완료 작업을 취소합니다.
- 320·390·768·1024·1440px 하위 탭·팝업과 전체 케이스·규칙·회원사 상세를 포함한 220개 화면 검사에서 가로 넘침·중복 ID·잘못된 중첩·JavaScript 오류가 없었습니다. 미정의 CSS 변수도 없으며, 수정 후 회귀 검사 133개·주요 흐름 20개·사진 검사 10개와 추가 상호작용 검사가 통과했습니다.

검수 범위는 가상 데이터와 브라우저 안의 업무 흐름입니다. 실제 통합 API, AI 모델 정확도, 서버 권한·성능, 운영 데이터 이관을 검증한 결과가 아닙니다.
